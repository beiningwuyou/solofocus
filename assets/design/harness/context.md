# Design Context — PGT 个人工作台

> 这份文档回答"为谁造、什么场景、该是什么感觉"。
> **这三件事无法从代码推断**——代码只说明造了什么。
> 任何 UI 生成任务开始前必须先读本文件。

---

## 1. 目标用户

**唯一用户：项目所有者本人（zzx）。**

不是"面向个人用户的产品"，是**一个人的专属工具**。这个区别决定了很多取舍：

| 通用产品需要 | 本项目 |
|-------------|--------|
| 新手引导流程 | ✗ 不需要。用户就是建造者，天然知道怎么用 |
| 教学型空状态 | ✗ 不需要。空状态只需说明"这里还没有数据"，不需要解释概念 |
| 保守的信息密度 | ✗ 可以更高。用户熟悉全部信息结构 |
| 防御性确认弹窗 | ✗ 克制使用。仅用于不可逆操作 |
| 功能发现性设计 | ✗ 不需要。可以有隐藏的键盘快捷键、专家向交互 |

**推论：优化"第一千次使用"，不是"第一次使用"。**

---

## 2. 使用场景

**长时间沉浸式操作。** 不是每天打开 3 分钟打卡，是长时间停留、连续工作、反复扫视。

这是本项目最重要的设计约束，直接推导出：

### 2.1 视觉疲劳是第一敌人

- **禁止高饱和大面积色块**。强色（blue / green / orange / violet / red）只能用于小面积语义标识：状态点、标签、图标、进度条。**绝不作为面板或区块背景**。
- **对比度要够，但不能刺眼**。正文用 `--text`（`#13213a`）而非纯黑；背景用 `#ffffff` 而非高亮白；已避免纯 `#000`，继续保持。
- **暗色模式是一等公民，不是附属功能**。长时间使用者大概率在夜间工作。任何新组件必须同时验证亮/暗两套，暗色不允许"能看就行"。

### 2.2 动效必须极度克制

**判断标准：这个动效在一天内第 50 次出现时，还能忍吗？**

- 允许：状态变化反馈（hover、focus、展开/收起）、页面淡入
- 禁止：装饰性动效、循环动画、弹性/回弹缓动、任何吸引注意力但不传递信息的运动
- 时长上限 0.28s（`--transition-slow`），常规用 0.15s / 0.2s
- 现有 `pulseGlow` 仅限启动屏，**不得扩散到常驻界面**

### 2.3 布局稳定性优先于视觉惊喜

- 同类页面结构保持一致，用户形成肌肉记忆后不应被打乱
- 避免内容加载导致的布局跳动（CLS）
- 不使用会改变元素位置的 hover 效果（如放大、位移）

## 3. 品牌调性

**继续极简克制。这是刻意的设计主张，不是默认选择。**

### 3.1 一句话定义

> 一件安静的专业工具。它不表达自己，它让内容表达。

参照系是 Linear、Notion 的克制侧，不是 Vercel 的高对比戏剧感，更不是任何带渐变光晕的 AI 产品审美。

### 3.2 明确的禁止清单

这些不是"不推荐"，是**禁止**：

- ✗ 渐变（背景渐变、文字渐变、边框渐变，一律不用）
- ✗ 玻璃拟态 / backdrop-filter 毛玻璃
- ✗ 发光效果 / neon / box-shadow 光晕
- ✗ 装饰性插画、吉祥物、emoji 作为界面元素
- ✗ 默认 Bento 卡片阵列（"万物皆卡片"）
- ✗ 卡片套卡片的嵌套容器
- ✗ 大图标 + 圆角容器的"英雄指标"模板
- ✗ 深色主题 + 霓虹点缀的泛 AI 审美

### 3.3 明确的正向主张

- **真白背景** `#ffffff`，不用灰白打底
- **深海军蓝** `#112c54` 作为品牌锚点与选中态
- **边框而非阴影**建立层次。阴影仅用于真正的浮层（modal / dropdown）
- **开放列表和表格优先**于卡片。数据密集场景下表格永远比卡片墙高效
- **Lucide outline 图标**，18–21px，stroke 约 1.9，不用 filled 图标
- 色彩只承担**语义**职责，不承担装饰职责

### 3.4 The AI Slop Test

> 把界面给人看，说"这是 AI 做的"，对方会立刻相信吗？

本项目的差异化不在视觉炫技，而在**信息密度与克制度的平衡**——高密度但不拥挤，安静但不寡淡。这是长时间使用工具应有的样子，恰恰是 AI 默认审美最不擅长的方向。

---

## 4. 排版

- 字体栈：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif`
- 中英混排为常态，字号选择需同时验证中文观感
- 字号阶梯见 `tokens.json` 的 `typography` 段
- **正文 14px 为基准**，比常规 Web 略小——服务于高信息密度
- 避免超过 3 级的字号层次出现在同一屏

---

## 5. 覆盖范围

**本 harness 仅服务 PGT 工作台应用（`.workbench-app`）。**

不覆盖：公众号配图、H5、对外内容物料。那些场景调性完全不同（需要吸引注意力，本项目需要不打扰注意力），若未来需要应另建独立 context，仅共用方法论层。

---

## 6. 与 impeccable skill 的职责边界

| 关注点 | 归属 |
|--------|------|
| token 一致性、间距、组件参数、暗色适配 | **本 harness**（强约束，不可协商） |
| 布局手法、层次处理、微交互质感、细节打磨 | **impeccable**（在 harness 约束内自由发挥） |
| 美学方向、大胆程度 | 已由本文件锁定为"极简克制"，impeccable 的 `bolder.md` **不适用于本项目** |

简言之：**harness 划定边界，impeccable 在边界内追求品质。**
